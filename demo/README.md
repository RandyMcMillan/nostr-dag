# nostr-dag Demo

`demo/` is the source of truth for the browser-facing application.  The build
system copies everything from here into `site/` before the server starts or
before GitHub Pages deploys.

## Structure

| Directory | Purpose |
|-----------|---------|
| `bridge/` | libp2p ↔ Nostr bridge viewer (peer discovery, relay status, presence) |
| `dag/` | NIP-34 DAG viewer (quorum sequences, event graph, Nostr publish) |
| `git/` | Decentralised Git viewer (clone repos via P2P bundle or CORS proxy) |
| `shared/` | Modules used by all pages (page shell, logger, protocol parsers) |
| `vendor/` | Vendored third-party libraries (nostr-tools, isomorphic-git, etc.) |

## Running locally

```bash
# Start the static file server + optional native P2P peer
P2P_ENABLE=1 cargo run --bin nostr-dag-server --features p2p,native

# Or use the Makefile target
make server
```

Open http://127.0.0.1:3000/git/ for the Git viewer.

## Decentralised Git (NIP-PIP)

The Git viewer can fetch repositories through two paths:

1. **libp2p P2P bundle** (primary) — a native `p2p-node` peer mirrors popular
   repos, bundles them, and advertises the bundle as NIP-PIP manifest events
   (kind 39078) + slice events (kind 39079) on the `nostr-dag-bridge` gossipsub
   topic.  The browser requests the bundle via gossipsub or, when the page is
   served from GitHub Pages (mixed-content blocks direct WebSocket dial), via
   public Nostr relays using kind 39077 requests.

2. **isomorphic-git CORS proxy** (fallback) — when no peer has the repo, the
   viewer falls back to cloning through the built-in proxy endpoint
   (`/proxy/`).

See `demo/git/GIT_PROXY.md` for the full protocol specification.

## Relay configuration

Both the native peer and the browser transport connect to a default set of
public Nostr relays:

- `wss://nos.lol`
- `wss://relay.nostr.com`
- `wss://relay.nostr.band`
- `wss://relay.primal.net`
- `wss://nostr.wine`
- `wss://top.testrelay.top`
- `wss://relay.pocketnostr.com`
- `wss://basspistol.org`
- `wss://relay.ngit.dev`

Override the native peer's relay list with the `NOSTR_DAG_RELAYS` environment
variable (comma-separated URLs).

## Mirror configuration

The native peer automatically mirrors a default set of repos on startup.  Add
more repos via the `GIT_MIRROR_REPOS` environment variable (comma-separated
URLs).

## Dependencies

All runtime dependencies are vendored in `demo/vendor/` so the demo works
offline and on GH Pages without relying on CDN availability.  The vendor files
are generated by `scripts/build-vendor.mjs`.
